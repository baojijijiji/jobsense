# JobSense

面向求职场景的个人经历管理、岗位匹配与简历编辑工具。

把分散的项目、科研和实习经历整理成可检索的档案，结合目标岗位挑选相关内容，经人工核对后生成和编辑中文简历，并跟踪后续投递进度。

> 发布候选草稿：配置说明、许可、干净安装和部署验收仍待完成。请勿直接部署。

## 功能

| 模块 | 用途 |
| --- | --- |
| 总览 | 查看档案概况、最近经历和当前简历，进入常用操作。 |
| 经历与成果 | 管理教育、项目、科研、实习和实践资料，记录贡献、技能和成果。 |
| 附件资料 | 保存和关联本机附件，支持基础检索、预览及下载；通用附件尚未接入账号云同步。 |
| 岗位匹配 | 本地关键词加权与类型轮询准备候选，再由 DeepSeek 进行语义比较、推荐和中文改写。 |
| 投递记录 | 跟踪申请进度，按职位类型、阶段和月份统计；AI 分析使用去标识汇总。 |
| 简历编辑 | 修改文字、栏目和排版，设置照片与字体，通过浏览器打印或另存 PDF。 |

账号模式下，经历、当前简历、投递记录、照片和偏好保存到 CloudBase。岗位简历历史每账号最多保留 30 条，可查看招聘原文、匹配依据、最初版本与最近修改版，并调阅继续编辑。

## 核心实现

- **候选召回与排序**：结合关键词加权、按类型轮询和语义比较，单次处理最多 12 段候选，推荐最多 3 段经历。
- **内容核对**：为 AI 要点保留原文依据，对引用、数字和部分职责表述进行规则校验，必要时补回原始量化成果；最终内容由用户确认。规则核对不等于完整语义事实核验。
- **账号资料同步**：使用 PostgreSQL 行级权限限制记录归属，以版本号处理多设备更新冲突。
- **AI 服务接入**：由 Vercel 函数校验登录身份，再请求 DeepSeek；API 密钥保留在服务端，数据库事务控制逐账号限额与并发。
- **历史快照**：保留招聘信息、匹配来源、简历内容、排版和适配后的照片；首次版本不随修改覆盖。
- **界面与导出**：暖灰香槟丝绸背景和玻璃工作台，支持深浅及自定义主题；简历保持白纸排版和独立字体设置。

## 本地运行

以下约定仓库中保留 `web/` 应用目录：

```powershell
cd web
pnpm install --frozen-lockfile
pnpm dev
```

在终端提示的固定本机地址访问。默认本地模式使用浏览器存储；使用本地 AI 改写需要由使用者配置自己的 DeepSeek API 密钥。未配置 AI 时，可使用经历整理、候选准备、简历编辑和本地投递管理。

```powershell
pnpm test
pnpm build
```

开发与构建脚本会从固定 PDF.js 依赖复制 PDF 渲染资源，无需把生成的 `public/pdf-assets/` 提交到源码仓库。

## 账号模式与部署

当前账号模式采用以下结构：

```text
浏览器工作台
├─ CloudBase 认证与 PostgreSQL：账号身份、私有资料和历史
└─ Vercel AI 函数：身份/归属校验与限额 → DeepSeek API
```

部署者需要配置自己的 CloudBase 环境、前端来源和 AI 后台地址，并在自己的服务端设置 DeepSeek 密钥。前端公开配置与服务端秘密须分开。

全新环境需按数据库脚本依赖完成表、RLS 与函数，再构建和部署前端与 AI 后台。发布前应补齐 `docs/deployment.md`；前端使用 VITE_CLOUDBASE_ENV_ID 配置环境 ID；web/public/ai-endpoint.json 需填写自己部署的 AI 后台地址。AI 函数运行环境需设置 CLOUDBASE_ENV_ID、JOBSENSE_SITE_ORIGIN 和 DEEPSEEK_API_KEY。完整部署与安全验证尚待完成。

## 验证与边界

项目已有自动测试覆盖资料读写、冲突、权限边界及历史保存等行为。此前一次功能检查通过 74 项测试，并有 12 项本地 PostgreSQL 引擎检查；这些结果不代替当前发布版本的干净安装、真实 CloudBase、多用户或端到端验证。

- AI 内容可编辑，可能遗漏信息或触发规则误拦，需要核对原始依据。
- 普通附件原文件当前以本机保存为主；账号照片与历史中的压缩照片已有独立同步实现。
- PDF 导出依赖浏览器打印；不同系统的字体、分页和显示仍需验收。
- 未完成可靠的全量离线能力、通用附件云同步和完整 OCR 流程。
- AI 服务由部署者配置和承担相应供应商用量；源码副本应连接自己的服务实例。
